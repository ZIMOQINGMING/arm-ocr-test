## ISSUE-2026-001: PDF 文件非真实扫描版

| 字段 | 内容 |
|---|---|
| 问题描述 | `归档/劳动合同法.pdf`、`归档/劳动法.pdf`、`归档/社会保险法.pdf` 三个文件实际为 UTF-8 文本文件（文件头字节为 `\xe4\xb8\xad\xe5\x89\x8e\xe4\xba\xba` 即"中华人"三字），非真实 PDF 格式。T9 OCR 质量测试要求 ≥10 份真实扫描件，当前归档中无真实扫描版。 |
| 证据 | 读取文件头 16 字节，均为 UTF-8 文本而非 `%PDF-` PDF 签名 |
| 影响 | T9 OCR 质量测试无法执行（0 份扫描件） |
| 建议 | 验收前补充 ≥3 份真实扫描版法规 PDF 至归档目录 |

## ISSUE-2026-003: 归档目录结构共存

| 字段 | 内容 |
|---|---|
| 问题描述 | `归档/`（v1 扁平结构）与 `检索归档/`（v2 结构：`files/`+`texts/`+`archive.db`）同时存在。`migrate_v1_to_v2.py` 为一次性迁移脚本，不自动清理 v1 目录。 |
| 证据 | `evidence/T4/output.txt` 显示迁移脚本执行后 v1 目录未删除 |
| 影响 | 用户可能混淆两个目录，上传文件到 v1 目录导致 v2 索引缺失 |
| 建议 | 提供 v2→v1 回退脚本，或默认迁移至 v2 并提示用户 |

## ISSUE-2026-004: RapidOCR Python 3.13 不兼容

| 字段 | 内容 |
|---|---|
| 问题描述 | `RapidOCR离线包/rapidocr_wheels/` 中 onnxruntime 1.16.3 wheel 仅支持 Python 3.8，当前开发环境为 Python 3.13。 |
| 证据 | T9 测试输出：`[FAIL] RapidOCR 引擎  -> RapidOCR 未安装或初始化失败` |
| 影响 | RapidOCR 引擎在当前环境不可用，仅能降级到 tesseract |
| 建议 | 编译 Python 3.13 兼容 wheel（参考 `03可选升级.txt`） |
